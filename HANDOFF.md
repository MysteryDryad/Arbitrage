# Arbitrage (Torn flip profit tracker): handoff

Script: `torn-flip-profit-tracker.user.js` (see `@version`; `VERSION` must match, `test.js` checks it). Tests: `node test.js` (needs `npm i --no-save jsdom fake-indexeddb`).
Runs in Torn PDA (iOS) and Tampermonkey. Read-only: reads the Torn API, never acts in the game. Data stays on the device.

## Branch
All work and pushes go to `claude/torn-flip-tracker-handoff-0o79ga` (the main branch for this project). Do not use other branches; `claude/serene-fermi-3tusq7` was merged into it and is retired.

## How it works
- `user/log` (v2, newest first) is paged into `state.txs`: item market, bazaar, trade, item send/receive, abroad and NPC shop buys/sells. Trade direction comes from the log (`Trade items incoming` = buy).
- `computeFlips` does FIFO per item; sales without a matching buy are "not counted", buys/sends without an amount "need a value".
- Receipts override log amounts: Weaver/TornW3B (API, own key, matched by trade ID), TornExchange and PawnHub pages (auto-added when opened, picked up from the GM `inbox` by the Torn page), PawnHub Balance page (matched to sends by item, quantity and time).
- One Sync button does everything (log, inbox, Weaver import, one re-read of the log for receipts whose trade is missing). Details of the last sync are in the debug sample (`lastSyncDetail`).
- Storage: full state in IndexedDB (shared by Torn pages); compressed backup in script storage (`statez`); `mergeState` folds in values from a newer copy so a stale page cannot overwrite receipt values.

- Crimes (v0.1.172): the log title is "Crime success item gain (new)" (money is "Crime success money gain (new)"); items are read from the entry data like other item entries, with the "gaining Nx Name" sentence as a fallback. Successes that gain items ("...successfully searching the cemetery gaining 3x Candle") become `channel: 'crime'` buys at amount 0 with `free: true` (stock at cost 0, never a gift). Money gains and failures are ignored. The sentence is searched for in the log entry's data/details/title, and the raw shape is unverified: if crime items still show "no matching buy" after Re-sync, copy the debug sample (it keeps crime entries with items). Unmapped item names are counted in `state.crimeUnknown`.

- Sync speed and background sync (v0.1.173-174): the log read saves state every 5 pages and at once when the tab is hidden (flushNow), so Continue resumes where it stopped; the button shows a running page count that survives a resume and pauses 500ms between pages; PawnHub and Weaver run in parallel after the log read; the Sync buttons show live progress. `autoSync` runs `syncAll({bg:true})` every 5 minutes while a Torn page is visible (panel can be closed): skipped before the first manual read, during a half-done read, while another sync runs, for 15 minutes after an error, and when another tab holds the `tfp_bglock` lock. Background syncs look at PawnHub only every 30 minutes. A userscript cannot run with no Torn page open.

- v0.1.176: "Item abroad sell" (item, quantity, value_each, total_value) is read as an abroad sale. If the log read stops partway, `syncAll` still runs the receipt inbox, PawnHub and Weaver on what was read, then reports "Log read stopped … Tap Continue" (a background sync rethrows so it backs off). Crime item gains use `data.items_gained` (map of item id to quantity), confirmed from a real entry.

- v0.1.177: download-speed slider (20 to 80 calls per minute, step 10, default 60, `syncRate`) in the setup "How far back, and how fast?" step and in Settings, with collapsed "Why is there a speed setting?" and "What happens after the first sync?" explanations. It sets the pause between log pages (`ratePause`: 60000/rate minus 250ms).

- v0.1.178: museum set exchanges and the points market. Log entries: `Museum exchange` (data.set, quantity = sets, points_received), `Points market sell/buy` (quantity, cost_each, cost_total), `Points ... use` (points_used, refills). Points are an item with id `POINTS_ID` (-1). `computeFlips` handles `dir: 'convert'` (uses up one of each set item FIFO, creates points lots carrying the cost, listed in `res.converts`, no profit yet) and `dir: 'use'` (refills leave stock, no profit effect). Set lists (`MUSEUM_SETS`: Plushie Set 13 items, Exotic Flower Set 11) are matched to item ids by name from Torn's item list; unknown sets or names go to `state.museumUnknown`. Only plushie and exotic flower sets are modelled so far. Older history needs Re-sync from start to pick these entries up.

- v0.1.179-182: ONE read path, driven by log type ids. `user/log` is requested with `log=` = `LOG_FILTER_IDS` (ids the script parses, derived by running the script's own title patterns over `fixtures/logtypes.json`, the output of `torn/logtypes`) plus `WATCH_IDS` (types it does not parse yet: they are only counted in `state.watched[title] = {id, n, first raw entry, last}` and shown in the debug sample under `watched`, so a user's copy shows which unmodelled types they have, with a raw entry to write the parser from; remove an id from WATCH_IDS when its parser exists). The only unfiltered reads are an emergency fallback (Torn refuses the filtered request for a non-key, non-rate reason: full read for 24h, `state.filterOffUntil`/`filterWhy`) and the Settings switch "Read every log type (slower)". There is no daily audit read. test.js checks the filter list against the fixture (every wanted title listed, nothing extra) and that WATCH_IDS are real, unparsed types. Daily `refreshLogTypes` (v0.1.183, needs the key's `torn=logtypes` selection; fails quietly without it, built-in list stays): calls `torn/logtypes`, runs `titleWanted` over it and keeps ids the built-in list lacks in `state.extraIds`, added to every request (debug sample `logFilter.extraIds/logTypesErr`). `KEYURL` is now `user=basic,log&torn=items,logtypes`, with a collapsed dropdown `keyHelpHtml()` under the link (setup and Settings) explaining each permission and why (`logcategories` dropped; the debug sample no longer calls it). "Item shop sell points" (4220, items sold to a shop for points) is no longer read as a cash sale (it would have counted points as dollars); it is on WATCH_IDS until a real entry is seen. A genuinely new kind of entry still needs a parser; regenerate `LOG_FILTER_IDS` from a fresh `torn/logtypes` when adding one. `seenTitles`/`seenExamples` only cover requested types while the filter is on.

- Release: everything from the download-speed slider through the watch list and shop-points fix ships together as **0.1.177-beta** (during development those steps were numbered 0.1.177 to 0.1.185, so the notes above use those numbers).

- v0.1.178 (committed locally, not pushed yet): minimise during the first sync. `autoSyncMode` lets a first or half-done log read continue by itself (also while the tab is hidden; backoff 2 min after a failure; a running read refreshes `tfp_bglock` every page so two tabs do not both read). The pause between pages uses a small Web Worker timer while the tab is hidden (a hidden tab's page timers drop to about one a minute); if the worker cannot start, a normal timer is the fallback. While a long read runs the 💰 button shows `⟳ <page>`. Limit: if the phone suspends the whole app (iOS), nothing can run until it is reopened; the position is saved when the tab is hidden, and the read then resumes by itself.

## UI (v0.1.131)
Full-screen panel (`#tfp-card`: header, scrolling `.tfp-body`, floating Sync, bottom nav). Tabs: Profit (range chips, running-profit graph you can touch, timeline newest first, 10 rows then "Show more", trade number/receipt link/player name only in a row's details, market rows show listing, Torn fee and received), Receipts (status, waiting list, add, recent), Items (by item/day/channel, item history opens under the item), Settings (Needs attention inbox with "Got it"/Dismissed, keys, backup, troubleshooting). `state.ack` holds dismissed ids (1 = dismissed, 0 = restored); `state.names` caches player names (looked up one at a time for visible rows). Market sale records gained `each`, `fee`, `anon` (older ones fill in after Re-sync from start).

## First-run setup (v0.1.157)
New installs (no saved key and no data) see a gated setup popup instead of the tabs: welcome, Torn key (checked on the spot with a log call; on PDA you can use PDA's key or a custom one), "Do you use PawnHub?", PawnHub key (checked against the API, can be skipped), history length (30/90/365 days), optional Weaver key, then Sync now. Closing with X brings it back the next time the 💰 button is used until "Sync now" finishes it (`setupDone`). Existing users are migrated silently (`migrateSetup`). Settings has "Run setup again". Background inbox/PawnHub tasks wait for setup.

## Known gaps / ideas
- RW weapons/armor (unique `uid` in log items), museum sets other than plushie and exotic flower, and cache opening are not modelled: need log examples of each (use Settings > Backup & troubleshooting > Copy debug sample; entries with museum/cache/ranked/item use/points titles are kept).
- PawnHub Balance page lists only the newest ~100 payments; older sends need a value or can be left out of profit. A PawnHub API was requested from its owner.
- Stock tab and inventory check were removed on purpose.
- For sharing: pick a licence, check name on Greasy Fork, add the receipt sites to the disclosure if their rules require it.
